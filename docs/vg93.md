# КР1818ВГ93 (WD FD1793) - reference notes for the FDC model

These are the facts the pin-level model of КР1818ВГ93 is built from.

Sources:

- **DS**: Western Digital, *FD 179X-02 Floppy Disk Formatter/Controller
  Family*, May 1980, marked "preliminary specification", 24 pages (bitsavers,
  `components/westernDigital/FD179X-02_Data_Sheet_May1980.pdf`). `p.N` is
  the page number printed on the page. Ru.wikipedia cites this document as
  the Western source for ВГ93.
- **WP**: ru.wikipedia, article "КР1818ВГ93". It calls the chip a functional
  analogue of the FD1793, made by «Квазар» and «Квантор», and cites
  Коваленко В.А. et al., «БИС контроллера КР1818ВГ93 для накопителя на
  гибком диске», *Микропроцессорные средства и системы* 1986 №3, pp. 3-8.
  That paper itself was not available online.
- **ZXR**: В. Сироткин, «TR-DOS для начинающих», *ZX-Ревю* 1997 №1-2
  (zxpress.ru `book_articles.php?id=942`). It has a pin table of all 40 pins.
- **TRP**: *TR-DOS для профессионалов и любителей*, 1993, Appendix 1
  (zxpress.ru `book_articles.php?id=1356`). It has pins 1-27 and the reset
  behaviour.
- **ST**: О. Сучков, *Sinclair Town* #02, 1994 (zxpress.ru
  `article.php?id=9546`). It gives the open-drain pins and the supply figures.
- **TD**: NS4 technical description, `$MS0515_DATA/docs/NS4-techdesc.md`:
  §4.11 / Рис.23-24, Рис.15-16, Приложение 1.
- **SCH**: the MS 0515 board CAD library strings,
  `$MS0515_DATA/scans/mick-pcad/strings.txt` (symbol `1818VG93`, part DD1).
- **EMU**: the emulator. `src/core/src/floppy.c` and `src/core/src/board.c`
  are in the ms0515 repository.

All the Soviet sources are secondary: magazine and book tables, with OCR damage
in places. No ТУ or plant datasheet for ВГ93 was found. Where they disagree
with DS, DS is used and the conflict is listed in the last sections.

Conventions:

- **[derived]** marks arithmetic on figures from the documents.
- **[diagram]** marks a fact read from a flowchart or a timing drawing.
- `1x` / `2x` means the CLK = 1 MHz / 2 MHz figure. DS states most times for
  2 MHz and says they "double when CLK = 1 MHz" (DS p.6, p.21, p.22 note 5).
  **The MS 0515 runs the chip at 1 MHz** (TD Рис.23).

## 1. Which part ВГ93 is

- The 1793 is the 1791 with TRUE (non-inverted) DAL lines. The 1791 and 1795
  have an inverted bus. The 1795 and 1797 replace RG with the side-select
  output SSO. The 1792 and 1794 are single-density only (DS p.1 table, p.2).
- ВГ93 is called the FD1793 analogue (WP). Both Soviet pin tables name the data
  lines D0-D7 / DB0-DB7 with no inversion mark, while they mark W, CS, R and
  CLR as active low (ZXR, TRP). **So the model uses a true bus: a 1 on DALn is
  a 1 in the register.** No source states the polarity in so many words (see
  Open questions).
- ВГ93 has RG on pin 25, not SSO (ZXR: RSTB "read strobe", TRP: "RSTB (RG)").
  It has no side output. On the MS 0515 the side comes from system register A
  bit 3 (TD Рис.15).
- Process: N-channel silicon-gate MOS, TTL-compatible on all inputs and outputs
  (DS p.2). ВГ93 is n-MOS, 6 µm, about 5600 elements (WP).

- SCH's library symbol lists STEP DIRC RES GND +5V TEST HRDY CLK RSTB RAWR HLD
  TR43 WSTB CPRDY WFDE TR00 WPRT DDEN DRQ INTRQ +12V. The board's net list is
  not decoded here.

## 3. Bus interface and registers (DS p.2, p.4-6)

| A1 A0 | -RE (read) | -WE (write) |
|---|---|---|
| 0 0 | Status | Command |
| 0 1 | Track | Track |
| 1 0 | Sector | Sector |
| 1 1 | Data | Data |

- The DAL drives only while -CS and -RE are both low. It receives while -CS and
  -WE are low (DS p.6).  The model drives it a master tick (8.3 ns) after
  -CS and -RE fall and lets it go a tick after they rise: inside tDACC.
- **Data shift register (DSR)**: assembles serial data from RAW READ, or
  shifts serial data out to WD (DS p.4).
- **Data register (DR)**: the holding register between the DSR and the bus.
  For Seek it holds the target track (DS p.4).
- **Track register (TR)**: incremented on each step in and decremented on each
  step out. Compared with the ID track byte on read, write and verify. Must not
  be loaded while busy (DS p.4).
- **Sector register (SR)**: compared with the ID sector byte. Must not be
  loaded while busy (DS p.5).
- **Command register (CR)**: write only. Must not be loaded while busy, except
  with Force Interrupt (DS p.5, p.8).
- **Status register**: read only (DS p.5).
- **CRC**: G(x) = x^16 + x^12 + x^5 + 1. It covers everything from the address
  mark up to the CRC bytes, and the register is preset to all ones (DS p.5).
- **Access after a write**: after writing the sector, track or data register,
  that register cannot be read back for at least 4 µs (MFM). After writing the
  command register, status is not valid for about 28 µs (FM) / 14 µs (MFM).
  At 1 MHz these become 8 / 56 / 28 µs (DS p.20 note 2) [derived].

### 3.1 Status bits (DS p.23, Table 6)

| Bit | Type I | Read Address | Read Sector | Read Track | Write Sector | Write Track |
|---|---|---|---|---|---|---|
| S7 | NOT READY | NOT READY | NOT READY | NOT READY | NOT READY | NOT READY |
| S6 | WRITE PROTECT | 0 | 0 | 0 | WRITE PROTECT | WRITE PROTECT |
| S5 | HEAD LOADED | 0 | RECORD TYPE | 0 | WRITE FAULT | WRITE FAULT |
| S4 | SEEK ERROR | RNF | RNF | 0 | RNF | 0 |
| S3 | CRC ERROR | CRC ERROR | CRC ERROR | 0 | CRC ERROR | 0 |
| S2 | TRACK 0 | LOST DATA | LOST DATA | LOST DATA | LOST DATA | LOST DATA |
| S1 | INDEX | DRQ | DRQ | DRQ | DRQ | DRQ |
| S0 | BUSY | BUSY | BUSY | BUSY | BUSY | BUSY |

Under Type I status (DS p.23):

- S7 is the inverse of READY, ORed with MR.
- S6 is the inverse of -WPRT.
- S5 is HLD AND HLT.
- S2 is the inverse of -TR00.
- S1 is the inverse of -IP.
- S3 is a CRC error in an ID field.

Under Type II/III status (DS p.23):

- S5 on a read is 1 for a deleted data mark (F8) and 0 for a data mark (FB).
- S3 with S4 set means an error in an ID field. Without S4 it means an error in
  the data field.
- S2 means the CPU missed a DRQ within one byte time.
- S1 is a copy of the DRQ pin.

When a command arrives (DS p.16):

- Any command but Force Interrupt sets BUSY and updates or clears the other
  bits for the new command.
- Force Interrupt while busy resets BUSY only.
- Force Interrupt while idle resets BUSY and gives Type I status.

## 4. Commands (DS p.8, Tables 2-5)

| Type | Command | 7 6 5 4 | 3 2 1 0 |
|---|---|---|---|
| I | Restore | 0 0 0 0 | h V r1 r0 |
| I | Seek | 0 0 0 1 | h V r1 r0 |
| I | Step | 0 0 1 u | h V r1 r0 |
| I | Step In | 0 1 0 u | h V r1 r0 |
| I | Step Out | 0 1 1 u | h V r1 r0 |
| II | Read Sector | 1 0 0 m | S E C 0 |
| II | Write Sector | 1 0 1 m | S E C a0 |
| III | Read Address | 1 1 0 0 | 0 E 0 0 |
| III | Read Track | 1 1 1 0 | 0 E 0 0 |
| III | Write Track | 1 1 1 1 | 0 E 0 0 |
| IV | Force Interrupt | 1 1 0 1 | I3 I2 I1 I0 |

Flags:

- **h**: load the head at the start (1) or unload it (0).
- **V**: verify on the destination track.
- **r1 r0**: step rate.
- **u**: update the track register on Step commands.
- **m**: multiple records.
- **S** (bit 3, 1791/3 only): the side value to compare.
- **C** (bit 1): enable the side compare.
- **E**: 15 ms delay (at 2 MHz).
- **a0**: 0 writes the data mark FB, 1 the deleted mark F8.
- The 1795/7 use bit 1 as SSO and bit 3 as the sector-length flag b. That does
  not apply to ВГ93.

### 4.1 Step rates (DS p.6, Table 1)

| r1 r0 | 2 MHz, TEST=1 | 1 MHz, TEST=1 | 2 MHz, TEST=0 | 1 MHz, TEST=0 |
|---|---|---|---|---|
| 00 | 3 ms | 6 ms | 184 µs | 368 µs |
| 01 | 6 ms | 12 ms | 190 µs | 380 µs |
| 10 | 10 ms | 20 ms | 198 µs | 396 µs |
| 11 | 15 ms | 30 ms | 208 µs | 416 µs |

- The rates do not depend on DDEN (DS p.6, Table 1).
- STEP pulse: 2 µs (MFM) or 4 µs (FM) at 2 MHz (DS p.6), "2 or 4 µs" with
  note 5 (DS p.22). That gives 4 / 8 µs at 1 MHz [derived].
- DIRC is valid 12 µs before the first step pulse (DS p.6). That is 24 µs at
  1 MHz [derived], given that TDIR carries note 5 (DS p.22).

### 4.2 Head load, HLT, settling (DS p.6-7, p.9)

- **HLD rises** at the start of a Type I command when h=1, at the end of a
  Type I command when V=1, and on any Type II/III command.
- **HLD falls** on a Type I command with h=0 and V=0, or after 15 index pulses
  while idle (not busy). Page 9 says "15 revolutions".
- **Type I with h=1, V=0**: HLD is set at the start, HLT is not sampled, and
  there is no 15 ms delay.
- **Type I with h=0, V=1**: HLD is set near the end, then a 15 ms delay, then
  the chip waits for HLT=1.
- **Type I with h=1, V=1**: HLD is set at the start. After the last step comes
  the 15 ms delay, then the wait for HLT.
- **Type II/III**: with E=0, HLD is set and HLT is sampled until true. With
  E=1, HLD is set, then the 15 ms delay, then HLT is sampled.
- **The 15 ms delay** is 30 ms at 1 MHz and zero when TEST=0 (DS p.6;
  flowchart notes p.10, p.11, p.15).
- **HLT** normally comes from a one-shot fired by HLD's rise. Head engage takes
  30-100 ms; the drawing shows 50-100 ms (DS p.7) [diagram].

### 4.3 Type I flow (DS p.9-10 flowcharts [diagram], text p.9-10)

1. Set BUSY. Reset CRC error, seek error, DRQ and INTRQ. Set or reset HLD
   from h.
2. Step In sets the direction and Step Out resets it. Step keeps the previous
   direction. The flowchart does not show what Step uses after a reset (see
   Open questions).
3. **Restore** loads FFh into TR and 00h into DR, then runs as Seek.
4. **Seek and Restore loop**:
   - The DR is copied to the DSR.
   - If TR = DSR, go to verify.
   - Otherwise the direction is set to in if DSR > TR, else to out.
   - TR changes by ±1.
   - If TR00 is active and the direction is out, TR is loaded with 0 and the
     command goes to verify without stepping.
   - Otherwise one step pulse is issued, followed by the r1 r0 delay, and the
     loop repeats.
5. **Step, Step In, Step Out**: TR changes by ±1 only if u=1. The track-0
   check and one step pulse follow, then the r1 r0 delay, then verify.
6. **Restore with TR00 never active**: after 255 step pulses the command
   stops, sets the seek error and interrupts (DS p.10). Note: with FFh in TR,
   the Seek loop itself counts 255 steps to 0.
7. **Verify** (V=1):
   - Set HLD, wait 15 (30) ms, then wait for HLT.
   - Read the first ID field and compare its track byte with TR.
   - A match with a good CRC ends the command with no error.
   - A mismatch with a good CRC sets the seek error (S4).
   - A match with a bad CRC sets S3, and the next ID is tried.
   - The time limits conflict: p.9 text says 4 revolutions, p.6 text says 5,
     and the flowchart on p.10 says "5 index holes". On timeout, S4 is set.
8. The end: INTRQ is set and BUSY reset. With V=0 that happens right after
   the last step delay.

### 4.4 Type II (DS p.10-13, flowcharts p.11-12 [diagram])

1. Set BUSY. Reset DRQ, LOST DATA, RNF, S5, S6 and INTRQ.
2. If READY is low: INTRQ, BUSY reset, nothing done (DS p.8).
3. Set HLD. If E=1, wait 15 (30) ms. Wait for HLT=1.
4. TG43 = (TR > 43) (DS p.8, p.11).
5. A write command with -WPRT low ends with INTRQ and S6.
6. **ID search**:
   - Over 5 index pulses (flowchart p.11; the text on p.11 says 4
     revolutions), an IDAM is required with ID track = TR, ID sector = SR and,
     if C=1, side LSB = S (p.12).
   - The length byte is kept: 00/01/02/03 → 128/256/512/1024 (DS p.11).
   - A bad ID CRC sets S3 and the search goes on.
   - A timeout sets RNF.
7. **Read**:
   - The data address mark must come within 30 bytes (FM) or 43 bytes (MFM) of
     the last ID CRC byte, else RNF (DS p.12).
   - The DAM type goes to S5.
   - Each assembled byte is moved DSR→DR and raises DRQ. If DRQ is still set
     when the next byte is moved, that byte is lost, LOST DATA is set, and
     reading goes on.
   - At the end of the field, a CRC error sets S3 and ends the command even
     when m=1 (DS p.12-13).
8. **Write** (DS p.13 text, p.12 flowchart):
   - After the ID CRC, wait 2 byte times, then raise DRQ, then wait 8 more
     byte times.
   - If the DR has not been loaded, the command ends with LOST DATA.
   - Wait 1 more byte time. In MFM wait 11 more.
   - So WG rises 11 bytes (FM) or 22 bytes (MFM) after the ID CRC [derived;
     agrees with the p.13 text].
   - Write 6 bytes of 00 (FM) or 12 bytes (MFM), then the DAM chosen by a0. In
     MFM, the 3 A1 bytes come first (DS p.13 note).
   - Then, per byte: DR→DSR, set DRQ, write the byte. A byte not loaded in time
     sets LOST DATA and a 00 byte is written; the command goes on.
   - Then 2 CRC bytes and one FF byte, then WG falls.
9. **m=1**: SR is incremented and the search runs again. This continues until
   SR exceeds the sectors on the track (ending with RNF, DS p.12) or a Force
   Interrupt arrives.
10. WF low while WG=1 ends the command and sets S5 (DS p.4, p.7).

### 4.5 Type III (DS p.13-16)

- **Read Address**:
  - The ready check, E delay, HLT wait and TG43 update are as for Type II.
  - The next ID field gives 6 bytes (track, side, sector, length, CRC1,
    CRC2), each with its own DRQ.
  - The CRC is checked and S3 set on an error.
  - The ID track byte is copied into the **sector register**.
  - Timeout: 6 index pulses → RNF (flowchart p.16).
- **Read Track**:
  - Starts at the leading edge of the index pulse and ends at the next one.
  - Every byte goes out with a DRQ, gaps included. There is no CRC check.
  - Byte framing re-synchronises on each address mark.
  - RG is not activated. LOST DATA is set if the DR is still full (DS p.13,
    p.15).
- **Write Track**:
  - Ready, E/HLT and TG43 are as for Type II. -WPRT low → INTRQ and S6.
  - DRQ rises at once. If it is not serviced within 3 byte times, the command
    ends with LOST DATA (flowchart p.14). The text on p.13 says instead that it
    ends if the DR is still empty at the index pulse.
  - Writing starts at the index pulse and ends at the next one, which sets
    INTRQ.
  - A byte missing when needed is written as 00, with LOST DATA set.
  - Control bytes are listed below (DS p.14). The CRC is preset by F8-FE in FM
    and by F5 in MFM (DS p.13).

| DR | FM (DDEN=1) | MFM (DDEN=0) |
|---|---|---|
| 00-F4 | data, clock FF | data in MFM |
| F5 | not allowed | A1 with a missing clock (bits 4-5), CRC preset |
| F6 | not allowed | C2 with a missing clock (bits 3-4) |
| F7 | 2 CRC bytes | 2 CRC bytes |
| F8-FB | data, clock C7, CRC preset | data in MFM |
| FC | data, clock D7 | data in MFM |
| FD | data, clock FF | data in MFM |
| FE | data, clock C7, CRC preset | data in MFM |
| FF | data, clock FF | data in MFM |

### 4.6 Type IV: Force Interrupt (DS p.8, p.16)

- It may be loaded at any time. A running command is terminated.
- I0: interrupt on a not-ready → ready transition.
- I1: interrupt on a ready → not-ready transition.
- I2: interrupt on every index pulse.
- I3: interrupt at once. This one "requires reset": per the note, only a
  Force Interrupt with I3-I0 = 0 lets this interrupt be cleared by a later
  command write or status read.
- I3-I0 = 0: the command is terminated, BUSY is reset, and there is no
  interrupt.

### 4.7 INTRQ and DRQ (DS p.3, p.6)

- INTRQ rises at the end of every command. It falls on a status read or a
  command write. It is also raised when a Force Interrupt condition is met.
- DRQ falls when the DR is read (read commands) or loaded (write commands).
- During Type II/III, DRQ also shows as status bit 1.
- Byte period: 16 µs MFM / 32 µs FM at 2 MHz (DS p.19-20 drawing). That is
  32 µs MFM at 1 MHz [derived].
- Worst-case service time from DRQ (2 MHz): read 27.5 µs FM / 13.5 µs MFM
  (DS p.19), write 23.5 µs FM / 11.5 µs MFM (DS p.20). At 1 MHz MFM that is
  27 µs (read) and 23 µs (write) [derived].

## 5. Read channel: RAW READ, RCLK, address marks

- **RAW READ** is one 250 ns pulse per flux transition (DS p.7):
  - Tpw is 100 min, 200 typ ns (DS p.20).
  - Note 1 (DS p.22): normally 100-300 ns. Any width is allowed if the pulse
    lies entirely inside one window. A pulse that spans both windows must be
    under 300 ns (MFM) or 600 ns (FM) at 2 MHz, doubled at 1 MHz.
- **RCLK** is a nominal square wave from the separator, with one window per
  half-period (DS p.20, Input Data Timing table):

  | Diskette | Mode | DDEN | CLK | Ta (half) | Tb (half) | Tc (period) |
  |---|---|---|---|---|---|---|
  | 8" | MFM | 0 | 2 MHz | 1 µs | 1 µs | 2 µs |
  | 8" | FM | 1 | 2 MHz | 2 µs | 2 µs | 4 µs |
  | 5" | MFM | 0 | 1 MHz | 2 µs | 2 µs | 4 µs |
  | 5" | FM | 1 | 1 MHz | 4 µs | 4 µs | 8 µs |

- The pulse and the RCLK edges must not coincide: Tx1 (RCLK hold to RAW READ)
  ≥ 40 ns and Tx2 (RAW READ hold to RCLK) ≥ 40 ns (DS p.20).
- RCLK may be either level while RAW READ is low (DS p.22 note 4).
- tbc is nominally 2 µs (MFM) / 4 µs (FM) at 2 MHz, doubled at 1 MHz
  (note 3).
- RCLK may come from a PLL, one-shots or counters (DS p.7). A PLL separator is
  recommended for 8" MFM (note 2).
- **RG** (DS p.7):
  - FM: RG goes true after 2 bytes of zeros. An address mark must follow
    within 10 bytes, or RG drops and the search restarts.
  - MFM: RG goes true after 4 bytes of 00 or FF; the mark must follow within
    16 bytes.
  - RG then stays true "as long as the chip derives useful information from
    the data stream".
- **VFOE** (pin 33 with WG=0) goes low when HLD and HLT are both true, the
  settling time (if any) has expired, and the chip is inspecting data. On the
  1791/3 it stays low until the end of the data field (DS p.4, p.7).
- **Marks** (DS p.13-14, p.17):
  - FM: FE with clock C7 (IDAM), FB/F8 with clock C7 (DAM), FC with clock D7
    (index mark).
  - MFM: the IDAM and DAM are preceded by three A1 bytes with the clock
    transition between bits 4 and 5 missing. The index mark is preceded by
    three C2 bytes with the clock between bits 3 and 4 missing.
  - The AM detector finds ID, data and index marks during read and write
    (DS p.5).
  - DS does not describe how the detector frames bits or picks the data
    window from the two RCLK halves (see Open questions).
- **MFM rule** (TD §4.11, Рис.24):
  - A "1" is a pulse in the middle of its bit cell.
  - A clock pulse sits on a cell boundary only between two "0"s.
  - Pulses are 1T, 1.5T or 2T apart, with T = 4 µs on the MS 0515, which is
    250 kbit/s.
  - So the A1 sync byte is the cell stream 0100 0100 1000 1001 (4489h) and
    C2 is 5224h [derived from that rule and DS's missing-clock positions].

### 5.1 What the model has to feed the chip from an image

The images are bare sector dumps: 80 tracks × 10 sectors × 512 bytes per side
(EMU `floppy.h`: FDC_TRACKS, FDC_SECTORS, FDC_SECTOR_SIZE). They hold no gaps,
IDs, marks or CRCs. A bit-level drive model must therefore synthesise:

- **One revolution**: 200 ms at 300 rpm, which is 6250 MFM bytes at 250 kbit/s
  (EMU, TRACK_BYTES) [derived].
- **The index pulse**: ≥ 10 µs (TIP, DS p.22, note 5 → 20 µs at 1 MHz)
  [derived].
- **A System-34-style layout** (DS p.18, minimum MFM gaps):
  - Gap I: ≥ 32 × 4E.
  - Per sector:
    - 12 × 00, 3 × A1 (4489), FE.
    - C, H, R, N = track, side, sector 1..10, N = 02 (512 bytes).
    - 2 CRC bytes.
    - Gap II: exactly 22 × 4E.
    - 12 × 00, 3 × A1, FB, 512 data bytes, 2 CRC bytes.
    - Gap III: ≥ 24 × 4E (DS's table reads "24 bytes 4E, 3 bytes A1").
  - Gap IV filling the rest.
  - The index mark is optional for the 179X (DS p.18).
  - What the MS 0515's own formatters write is in `sim/board/drive.h`
    (`omega()`, `vvv()`, `fdz()`), disassembled from the originals in the
    collection (`software/format/`): sectors 1..10 in order with no
    interleave; ОМЕГА's index mark is four C2s and no FC, FDZ has none;
    ОМЕГА's FORMH writes H = 0 on the upper side.
- **The pulse train**: the MFM cell stream turned into RAW READ pulses
  (≈ 200-500 ns low at 1 MHz), plus a 4 µs RCLK whose half-periods bracket the
  clock and data cells with ≥ 40 ns margins. That is a model of the board's
  separator. On the MS 0515 it is a digital PLL (TD §4.11: «цифровой
  инерционный ФАПЧ»).
- **The drive lines**: READY, -TR00, -WPRT and HLT also come from the drive
  model, and STEP and DIRC go to it.

## 6. Write channel: WG, WD, precompensation (DS p.4, p.7, p.21)

- **WG** rises only after the first data byte has been loaded in answer to DRQ
  (DS p.7).
- **WD** pulse width Twp: FM 450/500/550 ns, MFM 150/200/250 ns (min/typ/max)
  at 2 MHz. Pin 31's text says 250 ns MFM / 500 ns FM.
- **WG ↔ WD**: Twg (WG to the first WD) is 2 µs FM / 1 µs MFM, and Twf (last
  WD to WG off) is 2 µs FM / 1 µs MFM.
- **Tbc** (write data cycle): 2, 3 or 4 µs, ±CLK error. All of these double at
  1 MHz (DS p.21 header).
- **WD is timed by CLK**:
  - At 1 MHz, WD is valid ≥ 100 ns before the CLK edge (Twd1) and ≥ 100 ns
    after it (Twd2).
  - At 2 MHz these are ≥ 50 and ≥ 30 ns.
  - The drawing (DDEN=0) puts the 500 ns window on the rising edge of CLK at
    1 MHz (DS p.21) [diagram].
- **EARLY / LATE**:
  - Active high, valid for the whole WD pulse.
  - Both low means nominal. The shift itself is done outside the chip
    (one-shots or delay lines).
  - Ts and Th (EARLY/LATE setup to WD and hold from WD) are each ≥ 125 ns in
    MFM (DS p.7, p.21).
  - **Which bit patterns raise EARLY or LATE is not given.**
- On the MS 0515, the chip feeds a «схема предкомпенсации» that drives the
  drive's write line (TD §4.11, Рис.23).
- A byte not supplied in time is written as 00 (DS p.6, p.13).

## 7. CLK (DS p.2, p.6, p.22)

- CLK is a free-running square wave: 2 MHz for 8", 1 MHz for mini-floppies.
  It is 1 MHz for both densities in the mini case.
- TCD1 (low) is 230 / 250 / 20000 ns and TCD2 (high) is 200 / 250 / 20000 ns
  (min / typ / max).
- The 20 µs maximum on either phase means the clock may not stop. Every
  internal time (step rates, the 15 ms delay, byte timing on write, the service
  windows) scales with CLK.
- The MS 0515 feeds "1 МГц" to the chip (TD Рис.23). A 7.5 MHz CPU clock
  divides to 1 MHz by 7.5, so the board must derive it some other way; that is
  not established here (Open questions).

## 8. Master reset (DS p.2, p.10, p.22, p.23)

- -MR low resets the device and loads 03h into the command register.
- While MR is active, Not Ready (S7) "is reset" (p.2). The S7 definition on
  p.23 says S7 is "ORed with MR" (conflict below).
- When -MR goes high, a **Restore** runs whatever the state of READY. Also, 01h
  is loaded into the sector register (p.2, p.10).
- The command 03h is Restore with h=0, V=0, r=11, which is the slowest rate:
  30 ms per step at 1 MHz [derived].
- TMR (MR pulse width) is ≥ 50 µs (p.22). Whether note 5 (doubling at 1 MHz)
  covers TMR cannot be told from the table layout.
- Soviet sources add the following (ZXR, TRP):
  - INTRQ is held at 0 during reset.
  - Afterwards SR = 01 and TR = 00.
  - TR = 00 follows from the Restore anyway.
- EMU's `fdc_reset` sets TR=0 and SR=1, but it runs no Restore and puts no
  value in CR.

## 10. How the MS 0515 uses it

- **Addresses** (TD Прил.1): 177640 is status (read) / command (write);
  177642 track, 177644 sector, 177646 data. TD §4.11's list says "команд (при
  чтении)", which is a slip. The emulator decodes A1:A0 from bus address bits
  2:1 (EMU `board.c`).
- **System register A** (177600, write; TD Рис.15):
  - Bits 1:0 select the drive (0-3).
  - Bit 2 is the motor, written as 0 = on.
  - Bit 3 is the side: per the TD, 0 = lower and 1 = upper. EMU takes bit 3
    = 1 as side 0, the opposite (see Conflicts).
- **System register B** (177602, read; TD Рис.16):
  - Bit 2 is the drive's READY line ("ГТВ Н", 0 = ready).
  - Bit 1 duplicates DRQ.
  - Bit 0 "duplicates INTR". The TD says 0 = ready for a command and 1 =
    executing. EMU returns 1 there while INTRQ is not set.
- The TD shows no FDC interrupt to the CPU, and EMU raises none. The software
  polls register B and the status register.
- **Format and channel**:
  - Two drives, both sides of a 133 mm diskette; each side is its own unit
    (DZ0-DZ3: TD Табл.17).
  - MFM (TD §4.11), 512-byte sectors, 10 sectors per track, 80 tracks
    (EMU `floppy.h`).
  - CLK 1 MHz (TD Рис.23).
  - The board around the chip: a digital PLL (ФАПЧ) between the drive's read
    line and RCLK / RAW READ, and a precompensation circuit after
    WD/EARLY/LATE (TD Рис.23).

### 10.1 The minimum subset the software relies on (from EMU `floppy.c`)

| Feature | Evidence in EMU |
|---|---|
| Restore, Seek, Step, Step In, Step Out; u flag; r1 r0 rates 6/12/20/30 ms | `start_type1`, `step_rate_table` |

Where EMU deviates from DS, so the lockstep comparison must allow for it:

- It settles 15 ms when V=1, against 30 ms at 1 MHz (DS p.6).
- It ignores E.
- Type II waits a fixed 5 ms instead of a rotational search.
- It never sets LOST DATA on Type II: it waits for the CPU instead.
- It has no index pulse.
- Restore has no 255-step limit.
- MR does not run a Restore.

## Conflicts between and within the sources

1. **Verify / search limit.**
   - Type I verify: p.6 says 5 revolutions, p.9 says 4, and the p.10
     flowchart says 5 index holes.
   - Type II search: the p.11 text says 4 revolutions, and the p.11 flowchart
     and the p.12 side-compare text say 5.
   - Read Address: the p.16 flowchart says 6.
2. **Write Track DRQ timeout**: 3 byte times (p.14 flowchart) against "by the
   index pulse" (p.13 text).
3. **FM FD control byte**: the p.14 flowchart groups FD with FE/F8-FB (clock
   C7, CRC preset). The table on the same page gives FD clock FF and no preset.
   The p.13 text says the preset happens for F8-FE.
4. **S7 under MR**: "reset during MR active" (p.2) against "ORed with MR"
   (p.23).
5. **WD pulse**: 250 ns MFM (pin 31 text) against 200 typ, 150-250 ns
   (p.21 table).
6. **HLD auto-unload**: "15 index pulses" (p.6) against "15 revolutions"
   (p.9). These are equivalent only if one pulse comes per revolution.
7. **Restore step limit**: 255 pulses (DS p.10) against 256 (ST).
8. **DDEN**: ZXR's table says 1 = double density. DS p.4 says 0 = double.
9. **TEST**: TRP says TEST=0 gives "400 ms per step". DS gives 368-416 µs at
   1 MHz.
10. **INTRQ meaning**: ZXR says 1 = ready for a command and 0 = busy; TD says
    register B bit 0 is 0 when ready. DS says INTRQ is set at completion and
    reset by a status read or command write. Both describe board-level or
    garbled readings, not the chip pin.
11. **Side bit in register A**: TD says 0 = lower. EMU treats 1 as side 0.

## Open questions

The model will have to settle these from the board, the emulator in lockstep,
a real chip, or a recorded choice.

1. **DAL polarity on ВГ93.** It is inferred from "1793 analogue" and the
   unbarred Soviet pin names. No document states it, and the board may add
   inverting transceivers. Check the MS 0515 schematic around DD1.
2. **ВГ93 against FD1793.** Any functional or timing difference. Wanted:
   Коваленко et al., МПСС 1986 №3, and the plant's ТУ / справочный лист.
   ST quotes an opinion that ВГ93 copies an older revision.
3. **Internal sequencing.** DS gives flowcharts, not cycles. Not given:
   - which CLK edge moves each output;
   - the latency from a command write to BUSY and from the last event to
     INTRQ;
   - how the step delay is counted (from the pulse's start or its end);
   - the exact instant DRQ rises relative to the byte boundary.
4. **Read framing.** Not given:
   - how the chip decides which RCLK half is the data window;
   - how it frames bytes before and after an AM;
   - what "window extension" (DS p.1 features) does;
   - how RG behaves during Read Address and verify.
5. **Precompensation rule.** Which MFM patterns raise EARLY or LATE is not
   given.
6. **Step direction after reset.** What a plain Step does before any Step
   In/Out.
7. **Whether TMR doubles at 1 MHz.** And what DAL, DRQ and INTRQ do during MR.
8. **Board wiring on the MS 0515.** Not established:
   - how the 1 MHz CLK is derived;
   - whether DDEN is tied low;
   - where HLT comes from (a one-shot, HLD, or tied high);
   - whether READY on the chip is the drive's READY;
   - TEST, WF/VFOE and -MR (is it the bus reset?);
   - how register B bit 0 relates to INTRQ.

   These are to be read off the schematic.
9. **What the MS 0515 formatter writes.** Gap lengths, the side byte in the ID
   field, and sector order (interleave) on the track. Images carry none of
   these, so the bit-level drive model must choose them. The choice must keep
   Gap II and the sync counts within DS p.18.
10. **Step rate used by the ROM and handlers.** Which r1 r0 the software
    issues is not recorded here. EMU accepts all four.
