# Intel 8251A (КР580ВВ51А) - reference notes for the USART model

These are the facts the pin-level model of КР580ВВ51А (board parts D22,
keyboard, and D38, С2 serial port) is built from. Sources:

- **DS**: Intel, *8251A Programmable Communication Interface*, order number
  205222-002, November 1986 (cover; the OCR text layer reads "1988").
  The copy read was mark-ogden.uk/files/intel/publications/
  `205222-002 8251A Programmable Communication Interface-Nov86.pdf`. Its
  pages are numbered `2-1`..`2-25`, and the waveform sheets are cited by
  their position (2-20 Tx/Rx clock and data, 2-21 read/write data cycles,
  2-22 control/port cycles, 2-23 async flag timing, 2-24 sync Tx, 2-25 sync Rx).
- **RE**: Rochester Electronics, *8251A*, Specification Number 8251A-CI (I)
  Rev A, 2012, 11 pages (cryptomuseum.com/telex/rs/ga082/files/P8251A.pdf).
  It reproduces the Intel electrical tables and waveforms, and is cited as
  "RE p.N".
- **TO**: the MS 0515 technical description, `$MS0515_DATA/docs/NS4-techdesc.md`,
  §4.10.1-4.10.2 (lines 1441-1693), Tables 12-16 and Figs. 19-22. Line
  numbers are given as `TO L.n`.
- **SU**: Soviet secondary pages, not primary references: microcpukp580.narod.ru/qe.htm
  (no source cited), elancev.narod.ru/texno/bb51/bb51.htm (a lab handout
  citing Хвощ, Варлинский, Попов, *Микропроцессоры и микро-ЭВМ в системах
  автоматического управления*, 1987), and hromatron.narod.ru (a lab handout).
  **No primary Soviet document (ТУ, a reference-book scan) was obtained**:
  promelec.ru and voltradio.ru were unreachable.
- **NET**: `netlist/nets.csv` lines 1403-1451 (sheet 5).

Conventions:

- **tCY** is one period of CLK (pin 20).
- A text marked **[derived]** is arithmetic on figures from the documents.
- A text marked **[diagram]** is read from a waveform drawing. Drawings have
  no tolerances.
- A text marked **[inference]** is not stated anywhere. It is a reading of
  the stated facts, and the open questions (§13) keep it there.

Nothing read separates КР580ВВ51А from the 8251A. The SU pages give the
same pins, the same bus truth table and the same command bits as the DS.
Every statement below is about the 8251A unless it is marked otherwise.

| | D22 (keyboard) | D38 (С2 port) |
|---|---|---|

- The addresses (TO Tables 12, 16) are: receive buffer 177440 / 177700,
  transmit buffer 177460 / 177720, status (read) and mode/command (write)
  177442 / 177702. Address bit 1 is C/D.
- The baud clock is timer channels 0 and 1 in mode 3 with N = 26 from 2 MHz,
  for 4800 baud (TO L.1423-1439). 2 MHz / 26 = 76.92 kHz, which is 16 ×
  4808 baud [derived].
- The ROM's mode word is `11 00 11 10` = 0316 octal: 2 stop bits, no
  parity, 8 bits, ×16 (TO Fig. 20 / L.1520-1583).
- TO gives no frequency for ТС2М. The net name suggests 2 MHz, which is not
  verified here. At 2 MHz, tCY = 500 ns is within 320-1350 ns (§10).

## 2. Bus interface

| C/D | -RD | -WR | -CS | Operation (DS p.2-3) |
|---|---|---|---|---|
| 0 | 0 | 1 | 0 | data register → bus |
| 0 | 1 | 0 | 0 | bus → data (transmit) |
| 1 | 0 | 1 | 0 | status → bus |
| 1 | 1 | 0 | 0 | bus → control (mode, sync character or command, by sequence) |
| X | 1 | 1 | 0 | bus 3-state |
| X | X | X | 1 | bus 3-state |

- **Write edge.** Data must be set up 150 ns before, and held 20 ns after,
  the trailing (rising) edge of -WR (tDW, tWD). The word is therefore taken
  at the rising edge of -WR [derived from DS p.2-17; RE p.3; DS p.2-21
  diagram].
- **TxRDY** falls within 400 ns of the **leading** edge of -WR (tTxRDY CLEAR;
  DS p.2-4, p.2-18).
- **Control outputs.** TxEN, DTR and RTS take effect within 8 tCY of the
  **rising** edge of -WR (tWC; DS p.2-18, p.2-22 note 1).
- **Read.** Data are valid within 200 ns of the falling edge of -RD (tRD),
  provided the address is valid before -RD falls (note 3). They float 10-100
  ns after -RD rises (tDF). RxRDY falls within 400 ns of the **leading**
  edge of -RD (tRxRDY CLEAR; DS p.2-18).
- **Status inputs.** -DSR and -CTS must be stable 20 tCY before a read for
  the status to show them (tCR; DS p.2-18). This includes the effect of CTS
  on the TxENBL circuitry (DS p.2-22 note 2).
- **Write recovery (tRV).** At least 6 tCY between writes, "for Mode
  Initialization only". Data may be written only when TxRDY = 1. The
  recovery between writes is 8 tCY in async mode and 16 tCY in sync mode
  (DS p.2-16 note 4, p.2-17). RE omits tRV.
- **Status update.** An event can take up to 28 tCY to reach the status
  (DS p.2-14, p.2-16 note 7; RE p.4 note 6). The update is **inhibited
  during a status read** (DS p.2-2, p.2-13).
- With -CS high, -RD and -WR do not affect internal operation (DS p.2-2).
  This is an 8251A enhancement.

## 3. Reset and the control-word sequence

- **RESET high** forces "Idle". The chip stays idle until a new set of
  control words is written (DS p.2-2). TxD is marking (DS p.2-4, p.2-8).
  SYNDET/BD becomes an output, low (DS p.2-7).
- **Sequence** (DS Fig. 7 / p.2-8): mode instruction → [sync character 1 →
  sync character 2, sync mode only] → command instruction. After that, every
  C/D = 1 write is a command (DS p.2-8, p.2-12). In single-sync mode the
  second sync character is skipped; in async mode both are skipped (Fig. 7
  footnote).
- **The mode can be changed only after a reset**, internal or external
  (DS p.2-8).
- **Internal reset.** Command bit 6 (IR) = 1 returns the chip to the
  mode-instruction format (DS Fig. 12 / p.2-13; TO L.1599-1601). A command
  reset also puts the device "Idle" (DS p.2-2).
- **Power-up.** The chip may come up expecting a mode, a sync character or a
  command. The safe sequence is three `00` writes with C/D = 1: the first is
  taken as a sync mode with two sync characters, and the other two as those
  sync characters. Then write `40` (IR) (DS p.2-12 note). TO L.1481-1485
  prescribes the same: three zero bytes, then "Сброс".
- **RxD initialisation (async only).** After a master reset, the receiver
  must first see a valid "1" on RxD before it searches for a start bit. This
  is done once per master reset (DS p.2-5). It keeps a line held in break
  from starting the receiver (DS p.2-2).

## 4. Mode instruction

### 4.1 Asynchronous (B2B1 ≠ 00) - DS Fig. 8 / p.2-9; TO Fig. 20, Tables 13-15

| Bits | Field | Values |
|---|---|---|
| 1:0 B2B1 | baud factor | 00 sync mode, 01 ×1, 10 ×16, 11 ×64 |
| 3:2 L2L1 | character length | 00 5 bits, 01 6, 10 7, 11 8 |
| 4 PEN | parity enable | 1 = enabled |
| 5 EP | parity type | 1 = even, 0 = odd |
| 7:6 S2S1 | stop bits | 00 invalid, 01 1, 10 1½, 11 2; **affects Tx only - Rx never needs more than one** |

- The parity bit is not counted in the length. The received parity bit
  cannot be read. With fewer than 8 bits, data sit in the low bus bits:
  unused bits are ignored on write and **read as 0** (DS p.2-9 note, Fig. 9).

### 4.2 Synchronous (B2B1 = 00) - DS Fig. 10 / p.2-11

| Bits | Field |
|---|---|
| 1:0 | 00 |
| 3:2, 4, 5 | length, PEN, EP as in async |
| 6 ESD | 1 = SYNDET is an input (external sync), 0 = output |
| 7 SCS | 1 = single sync character, 0 = double |

In external sync mode, double sync affects only Tx (Fig. 10 note).

## 5. Command instruction - DS Fig. 12 / p.2-13; TO Fig. 21 / L.1588-1626

| Bit | Name | 1 means |
|---|---|---|
| 0 | TxEN | transmit enable |
| 1 | DTR | -DTR pin low |
| 2 | RxE | receive enable |
| 3 | SBRK | TxD forced low (break) |
| 4 | ER | reset PE, OE, FE |
| 5 | RTS | -RTS pin low |
| 6 | IR | internal reset (back to the mode format) |
| 7 | EH | enter hunt (no effect in async) |

- A 0 in DTR or RTS lets the pin go back high [inference from "1-bit
  inverting output port"; DS p.2-4]. TO says that 0 "has no effect"
  (L.1607, 1623).
- Fig. 12 note: "Error Reset must be performed whenever RxEnable and Enter
  Hunt are programmed."
- SU (elancev) says that SBRK drives TxD **high**. That contradicts DS and
  TO, and is wrong.

## 6. Status register - DS Fig. 13 / p.2-14

| Bit | Name | Meaning |
|---|---|---|
| 0 | TxRDY | **transmit buffer empty, not gated** by CTS or TxEN (unlike the pin) |
| 1 | RxRDY | same as the pin |
| 2 | TxEMPTY | same as the pin |
| 3 | PE | parity error; reset by ER; does not stop operation |
| 4 | OE | overrun: a character arrived before the previous one was read; the old one is lost; reset by ER |
| 5 | FE | framing error (async): no valid stop bit; reset by ER |
| 6 | SYNDET/BRKDET | same as the pin |
| 7 | DSR | 1 when the -DSR pin is 0 |

- TO Fig. 22 labels bit 1 "ГПРД" and bit 0 "ГПРМ", which is swapped against

  The SU pages and the NJIT notes agree with Intel.
- TO L.1663-1669: the TxRDY pin also depends on CTS (pin 17) and on TxEN.
  This agrees with DS.

## 7. Asynchronous transmitter

- **Format.** A start bit (low), the data LSB first, the parity bit if it
  is enabled, then the stop bits (high) (DS p.2-9).
- **Shift edge.** Data are shifted out on the **falling edge of -TxC**, at
  1, 1/16 or 1/64 of the TxC rate (DS p.2-5, p.2-9). TxD changes no later
  than tDTx = 1 µs after that edge (DS p.2-18; DS p.2-20 / RE p.6 diagram).
  RE omits tDTx.
- **Bit lengths [derived].** At ×16, one bit is 16 TxC periods: start 16,
  each data or parity bit 16, stop bits 16 / 24 / 32 for 1 / 1½ / 2. At
  ×64 the bit is 64 periods. At ×1 it is 1 period; what 1½ stop bits are at
  ×1 is not given.
- **Start.** The transmitter cannot begin until TxEN = 1 and -CTS = 0
  (DS p.2-4, p.2-8). The DS gives **no delay** from the write to the start
  bit. In DS p.2-23 / RE p.9 [diagram] the start bit begins at a TxC edge
  shortly after the -WR of the first character.
- **TxRDY.** It falls on the leading edge of -WR. It rises again when the
  buffered character moves into the shift register. With the shifter idle,
  this happens right after the write [diagram, DS p.2-23]. Otherwise it is
  within tTxRDY = 14 tCY of the "center of last bit" of the character being
  sent (DS p.2-18). The pin is gated by CTS and TxEN, the status bit is not
  (DS p.2-14 note 1).
- **TxEMPTY.** High when there is nothing to send. It goes low when a
  character is written while the transmitter is enabled, and stays high
  while the transmitter is disabled (DS p.2-4). It rises within tTxEMPTY =
  20 tCY of the center of the last bit (DS p.2-18). The DS p.2-23 diagram
  shows this marked after the last stop bit.
- **TxEN or CTS removed** during transmission: everything written before
  the disable is still sent, and a character is never cut off in the
  middle (DS p.2-2, p.2-4). This is an 8251A enhancement.
- **Idle.** TxD is marking after a transmission unless SBRK is set
  (DS p.2-2, p.2-9).
- **Send break.** SBRK = 1 holds TxD low continuously (DS p.2-9, Fig. 12).
  Whether it acts at once or at a character boundary is not stated; the
  DS p.2-23 diagram is unclear (Q4).

## 8. Asynchronous receiver

- **Start detection.** A falling edge on RxD starts a start bit, and "the Rx
  baud counter starts here" (DS p.2-9; DS p.2-20 diagram). The start bit is
  checked again at its nominal centre, in ×16 and ×64 modes only. If RxD is
  still low there, the start bit is valid; otherwise it is ignored as a
  false start (DS p.2-5, p.2-9).
- **Sampling point.**
  - ×16: the centre sample is 8 RxC periods after the edge, then every 16
    periods (DS p.2-20 / RE p.6 [diagram]).
  - ×64: 32, then every 64 [derived; not given].
  - ×1: data are sampled on the RxC rising edge; there is no start check
    (DS p.2-9).
- **Sampling edge.** The rising edge of -RxC (DS p.2-5, p.2-7, p.2-9). In
  the diagram the internal sampling pulse comes ~3 tCY after that RxC edge
  and is about one tCY (tφ) wide [diagram, DS p.2-20]. This suggests that
  RxC is synchronised to CLK [inference].
- **Data.** The bit counter finds the centres of the data bits, the parity
  bit and the stop bit. **Only one stop bit is checked.** A low there sets
  FE. A parity mismatch sets PE (DS p.2-9).
- **RxRDY.** The character is loaded into the output register and RxRDY is
  raised (DS p.2-9). This happens within tRxRDY = 26 tCY of the center of
  the last bit (DS p.2-18). RxRDY needs RxE = 1: with RxE = 0 it is held
  reset (DS p.2-6). It is cleared by the leading edge of -RD on a data read
  (DS p.2-8, p.2-18).
- **Overrun.** If the previous character was not read, the new one replaces
  it and OE is set. **If the CPU is reading the data while the internal
  transfer happens, OE is set and the old character is lost** (DS p.2-6).
  Errors do not stop the receiver (DS p.2-10).
- **Break detect.** The output goes high when RxD stays low through two
  consecutive stop-bit sequences, counting the start, data and parity
  bits. It is also read as status bit 6. It is reset only by a master reset
  or by RxD returning to 1 (DS p.2-7). DS p.2-23 [diagram] shows FE set at
  the first all-zero character.

## 9. Synchronous mode (brief; the board does not use it)

- Tx: TxD is high until the first character is written. Characters are
  shifted on the falling edge of TxC at the TxC rate. When the buffer runs
  dry, sync characters are inserted, TxEMPTY = 1 and it does not drop
  during them (DS p.2-4, p.2-10).
- Rx: data are sampled on the rising edge of RxC. In hunt (EH), the buffer
  is compared with the sync character(s) at every bit. When they match,
  SYNDET goes high, in the middle of the last data or parity bit. A status
  read clears it (DS p.2-7, p.2-11, p.2-12).
- External sync: a high level on SYNDET starts assembly at the next RxC
  rising edge, and may be removed after one RxC (DS p.2-7, p.2-11).
  tES ≥ 16 tCY after the RxC rising edge (DS p.2-18). RE p.4 adds "before
  falling edge of RxC" as the maximum.
- tIS: internal SYNDET follows RxC by up to 26 tCY (DS p.2-18).
- EH also sets the buffer to all ones (DS p.2-12).

## 10. CLK against TxC/RxC

- f(CLK) must exceed 30 × the Tx or Rx bit rate (DS p.2-3).
- f(TxC) and f(RxC) are limited (DS p.2-16 note 5; RE p.4 note 4; DS: for
  ≤ 64K baud):
  - at ×1, ≤ 1/(30 tCY);
  - at ×16 or ×64, ≤ 1/(4.5 tCY).
- Pulse widths (DS p.2-18; DS p.2-20 diagram: tTPW is drawn as the low
  phase and tTPD as the high phase):

| | ×1 | ×16 / ×64 |
|---|---|---|
| tTPW / tRPW min | 12 tCY | 1 tCY |
| tTPD / tRPD min | 15 tCY | 3 tCY |
| fTx / fRx max | 64 kHz | 310 kHz (×16), 615 kHz (×64) |

- On the board, about 76.9 kHz at ×16 [derived]. With tCY = 500 ns, the
  limit 1/(4.5 tCY) = 444 kHz holds [derived].

## 12. 8251 versus 8251A (DS p.2-2, "Features and enhancements")

The 8251A, as against the 8251, has:

- separate control, status, data-in and data-out registers;
- automatic break detection;
- the Rx initialisation against break (§3);
- TxD always returning to marking;
- a TxEN-off that finishes the written data;
- no effect of -RD/-WR without -CS;
- a status read inhibiting the status update;
- double sync characters that must be contiguous, and EH filling the
  buffer with ones;
- a self-clearing external SYNDET flip-flop;
- sync up to 64K baud.

The original 8251 data sheet (Intel 8080 User's Manual, 1975) was not read.

## 13. Open questions

1. **КР580ВВ51А against the 8251A.** No primary Soviet document was read.
   The only evidence is the pin order and the command and status bits in
   the SU pages and in TO.
2. **"Center of last bit" for tTxRDY, tRxRDY and tTxEMPTY in async.** Is the
   last bit the last data or parity bit, or the (first) stop bit? The DS
   does not say. DS p.2-11 uses the same phrase for sync, where no stop
   bits exist.
3. **The delay from -WR (TxEN = 1, CTS = 0, idle) to the start bit.** Not
   given. Is the start bit aligned to a TxC falling edge, or to a ÷16 phase
   of a free-running counter?
4. **SBRK.** Does it take effect at once, or after the current character?
   And what happens to a character waiting in the buffer?
5. **How start-bit edges are detected.** By RxC rising edges, or by CLK? With
   ×16, is the edge resolved to one RxC period? Is the false-start check one
   sample?
6. **How TxC and RxC are synchronised to CLK** (§8 inference). This is
   implied by the tTPW/tTPD limits in tCY and by the 3 tCY sample pulse,
   but never stated.
7. **A data read while RxRDY sets.** OE is set and the old character is
   lost (DS p.2-6), but which character does the CPU get on that read? Is
   RxRDY left set?
8. **"Status update inhibited during status read".** Is a deferred event
   applied when -RD rises, or lost?
9. **Writes closer than tRV**, or a data write with TxRDY = 0: what happens
   (overwrite, or ignored)?
10. **The ×1 receive mode.** No start validation; is the sample at the first
    RxC rising edge after the start edge? And what are 1½ stop bits at ×1?
11. **The T-11's DATI before every DATO** (t11.md §9). A MOV to 177460 (C/D
    = 0) first reads that address. Does the board's decode assert -CS with
    -RD there, so that it reads the receive buffer and clears RxRDY? This
    needs the board's ВБ511 decode.
12. **The CLK frequency (ТС2М)** on the board needs confirming from the
    schematic.
