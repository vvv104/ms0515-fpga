# КР580ВИ53 (Intel 8253) - reference notes for the timer model

These are the facts the pin-level model of КР580ВИ53 is built from. The ВИ53
is a functional copy of the Intel **8253**, not of the 8254. Where the two
Intel parts differ, these notes follow the 8253. The 8254 appears only in the
places where it is a trap (§9).

Sources:

- **DS**: Intel, *8253/8253-5 Programmable Interval Timer*, order number
  231306-001, November 1986. Printed pages 3-51..3-61 (Intel data-book
  numbering). It is the archive.org item `i8253`
  (https://archive.org/details/i8253).
- **KS**: a three-page Russian sheet, *КР580ВИ53 - таймер*: pins, electrical
  parameters and timing. ChipDip library DOC005642462
  (https://static.chipdip.ru/lib/642/DOC005642462.pdf). The sheet does not
  say where it comes from. It is cited as KS p.1..3, which are its PDF pages.
- **CM**: *Программируемый таймер КР580ВИ53*, computer-museum.ru, 23.07.2002.
  It was read through the mirror
  https://demin.ws/projects/radio86/info/kr580/i8253.html. It cites Kramer &
  Wurtenberger, *Datenbuch Mikrorechner-Schaltkreise* (1989), and the
  справочник *Микропроцессоры* edited by Овечкин (Судостроение, 1988). CM has
  tables 1-4 and no page numbers.
- **WP**: ru.wikipedia, article "КР580ВИ53". It is secondary and cited only
  for the variants.
- **MP**: *The PC Emulation Book*, section "8253 Programmable Interval Timer"
  (https://book.martypc.net/support-chips/timer-8253). It is secondary,
  written from emulator work, and cited only where DS is silent. Every MP
  fact is marked **[secondary]**.

Conventions:

- `p.3-NN` is a DS printed page.
- A text marked **[diagram]** is read from DS Figure 7 (p.3-56) or from the
  waveforms (p.3-61).
- A text marked **[derived]** is a consequence of DS statements and is not
  printed in DS.
- `N` is the count that was written. The **CR** is the count register that
  the CPU writes. The **CE** is the counting element. These names come from
  the 8254 datasheet; DS calls both of them "count register".

## 2. Bus interface

### 2.1 Operation table (DS p.3-53)

| -CS | -RD | -WR | A1 | A0 | Operation |
|---|---|---|---|---|---|
| 0 | 1 | 0 | 0 | 0 | Load counter 0 |
| 0 | 1 | 0 | 0 | 1 | Load counter 1 |
| 0 | 1 | 0 | 1 | 0 | Load counter 2 |
| 0 | 1 | 0 | 1 | 1 | Write the mode word (control word register) |
| 0 | 0 | 1 | 0 | 0 | Read counter 0 |
| 0 | 0 | 1 | 0 | 1 | Read counter 1 |
| 0 | 0 | 1 | 1 | 0 | Read counter 2 |
| 0 | 0 | 1 | 1 | 1 | No operation, bus 3-state |
| 1 | X | X | X | X | Disabled, bus 3-state |
| 0 | 1 | 1 | X | X | No operation, bus 3-state |

- The table does not cover -RD = -WR = 0 with -CS low. It is not given.
- The control word register is write-only. A read at A1A0 = 11 is a no-op
  (DS p.3-53, p.3-58 "Read Operation Chart").

### 2.2 Edges

- **Write.** In the write waveform (DS p.3-61), tDW (data setup) and tWD
  (data hold) are measured to the **rising (trailing) edge of -WR**. tAW
  runs from A0-1/CS stable to the falling edge of -WR; tWA runs from the
  rising edge of -WR **[diagram]**. Data are therefore taken at the end of
  -WR **[derived]**.
- **Read.** In the read waveform (DS p.3-61), the data are valid tRD after
  the falling edge of -RD. The bus returns to high impedance within tDF after
  the rising edge of -RD. A0-1/CS are stable tAR before -RD falls and stay
  for tRA after it rises **[diagram]**.
- Read data are 3-state outside -RD (DS p.3-61). On the timing of the read:
  DS does not say whether the count byte is sampled at the falling edge of
  -RD, or followed while -RD is low. Not given.

## 3. Control word (A1A0 = 11; DS p.3-54)

`D7 SC1 | D6 SC0 | D5 RL1 | D4 RL0 | D3 M2 | D2 M1 | D1 M0 | D0 BCD`

| Field | Value | Meaning |
|---|---|---|
| SC | 00 / 01 / 10 | Counter 0 / 1 / 2 |
| SC | 11 | **Illegal** on the 8253. It is the read-back command on the 8254 (MP [secondary]). DS does not say what a write with SC=11 does. |
| RL | 00 | Counter latch command (§4.3) |
| RL | 01 | Read/load the LSB only |
| RL | 10 | Read/load the MSB only |
| RL | 11 | LSB first, then MSB |
| M | 000 / 001 | Mode 0 / 1 |
| M | X10 / X11 | Mode 2 / 3 (M2 is don't care) |
| M | 100 / 101 | Mode 4 / 5 |
| BCD | 0 / 1 | 16-bit binary / 4-decade BCD |

- Each counter has its own mode word, selected by SC. Counters may be
  programmed in any order. The count bytes need not follow the mode word
  immediately, but they must come in the number and order that RL sets
  (DS p.3-57; CM Table 3 gives the same).
- With RL = 01 or 10, the byte that is not written is not described. DS does
  not say whether it is zeroed or kept. MP says that writing a mode word
  initialises both halves of the CR to 0 **[secondary]**. Not given in DS.

## 4. Loading and reading

### 4.1 Load

- The CR is not transferred to the counter until the count is written (one
  or two bytes, per RL) **and then a rising edge followed by a falling edge
  of CLK** occur. A read before that falling edge may return invalid data
  (DS p.3-54, "Counter Loading").
- **Count 0 = maximum**: 2^16 in binary, 10^4 in BCD (DS p.3-57; CM).
- Mode 0, RL = 11, written while counting: the first byte **stops** the
  count and the second byte starts the new count (DS p.3-54). Mode 0 does
  not restart until the load is complete (DS p.3-57).
- Rewrites in the other modes are covered per mode in §6.

### 4.2 Simple read

- To get a stable count, the counter must be stopped by GATE or by gating
  CLK externally (DS p.3-58).
- With RL = 11, the first read returns the LSB and the second the MSB.
- **The entire read must be completed.** If two bytes are programmed, two
  bytes must be read before any load (WR) to the same counter (DS p.3-58).
  This is a requirement on software. What the chip does when the rule is
  broken is not given. MP says that a mixed read/write on the 8253 gives
  undefined results **[secondary]**. This implies that one byte-pointer
  flip-flop is shared by reads and writes **[derived, unconfirmed]**.
- CM repeats the rule: after reading only the LSB, the counter must not be
  reloaded.

### 4.3 Counter latch command

- The command is a control word with SC = counter, RL = 00 and D3..D0 = X.
  It latches the present count into a storage register. The next read(s) of
  that counter return the latched value while the counter keeps counting
  (DS p.3-58).
- It has no effect on the counter's mode (DS p.3-58; CM).
- The same rule applies: the whole programmed read (1 or 2 bytes, per RL)
  must be completed (DS p.3-58).
- The latch is released after it has been read **[derived]**.
- A second latch command before the first has been read: not given in DS.
  MP says it is ignored, which is also how the 8254 datasheet describes its
  own part **[secondary]**.
- Latch, then a write to the same counter before the read: not given.
- CM advises latching and reading one counter at a time, not latching all
  three and then reading them.

## 5. Counting

- The counter is a 16-bit **down** counter, binary or BCD (DS p.3-53,
  p.3-57).
- **Edges.**
  - The decrement happens on the **falling edge** of CLK. DS states this
    explicitly for mode 3 (p.3-55) and for the load (p.3-54).
  - The output delay tOD is specified from CLK↓ (p.3-60).
  - GATE setup and hold are specified around **CLK↑**: tGS before, tGH after
    (p.3-60, p.3-61).
  - So GATE is sampled on the rising edge and acted on at the falling edge
    that follows **[derived]**.
- **BCD**: a 4-decade down count. What happens when a value that is not BCD
  is loaded with BCD=1: not given.
- **Mode 0 wrap**: the counter keeps decrementing after terminal count
  (p.3-54). After 0 comes FFFF, or 9999 in BCD **[derived]**.
- **Rates.**
  - DS: DC to 2.6 MHz. tCLK ≥ 380 ns, the same for the 8253 and the 8253-5
    (p.3-51, p.3-60).
  - KS: the same 380 ns period (p.2).
  - CM and WP: КР580ВИ53 2 MHz, КР580ВИ53Д (the 8253-5 analog) 2.5 MHz. See
    §9.
  - DS Fig. 10 (p.3-58): an 8085 clock output must be reduced to 2 MHz or
    less before it drives an 8253-5 clock input.

## 6. Modes

The "[diagram]" counts below are the values DS Fig. 7 prints over successive
clocks after the event.

### Mode 0 - interrupt on terminal count

- **After the control word**: OUT is low (DS p.3-54; CM).
- **After the count is written**: OUT stays low and the counter counts.
- **Terminal count**: OUT goes high and stays high until a new mode word or a
  new count is written. Counting continues.
- **GATE (level)**: 1 enables counting, 0 disables it (Fig. 6). In Fig. 7,
  with a count m=5 and GATE dropped, the counter holds and then resumes, and
  OUT rises after A + B = m counting clocks **[diagram]**.
- **Rewrite**: see §4.1. The first byte stops the count and the second byte
  starts the new one.
- **Timing [diagram]**: WR n=4, then 4 3 2 1 0, and OUT rises at 0. With the
  load clock of §4.1, OUT rises on the (N+1)-th CLK↓ after the write
  **[derived]**. MP gives the same N+1 **[secondary]**.

### Mode 1 - programmable (retriggerable) one-shot

- **After the control word**: OUT is high in Fig. 7. DS gives no text on it.
  Not given in text.
- **Trigger**: OUT goes low "on the count following the rising edge" of GATE
  and high at terminal count (DS p.3-55). In Fig. 6 the rising edge (1)
  initiates counting and (2) resets the output after the next clock. Low and
  high GATE levels have no effect in this mode.
- **Retrigger**: any rising edge restarts the full count, so OUT stays low
  for N clocks after the last edge. In Fig. 7: 4 3 2, then 4 3 2 1 0.
- **Rewrite**: a new count loaded while OUT is low does not change the
  current pulse. It takes effect at the next trigger. The count can be read
  without affecting the pulse.
- **Count before the first trigger**: not given.

### Mode 2 - rate generator (÷N)

- **After the control word**: OUT stays high until after the count is loaded
  (DS p.3-55).
- **Running**: OUT goes low for one CLK period every N clocks, and the
  counter reloads automatically. In Fig. 7, n=4: 4 3 2 1 0(4) 3 2 1, OUT low
  while the count is 1 and high again at the reload.
- **Rewrite**: the current period is unaffected and the next period uses the
  new value.
- **GATE**:
  - Low: disables counting and **forces OUT high immediately**,
    asynchronously; tODG ≤ 300 ns from GATE↓ (Fig. 6, p.3-60). KS (p.2)
    limits this delay to the two generator modes, 2 and 3.
  - Rising edge: reloads the counter and initiates counting, so it
    synchronises the counter.
  - High: enables counting.
- **Note on CLK sources**: in modes 2 and 3, if CLK is not the system clock,
  GATE should be pulsed right after the WR of a new count (DS p.3-55).
- **N = 1**: not given in DS. MP calls it invalid **[secondary]**.

### Mode 3 - square wave

- **After the control word**: OUT is high, "similar to MODE 2" (p.3-55).
- **Even N**: the counter decrements by 2 on each CLK↓. At terminal count OUT
  toggles and the full count is reloaded. OUT is high for N/2 clocks and low
  for N/2.
- **Odd N, 8253 algorithm (DS p.3-55)**:
  - With OUT high, the first clock after the load decrements by 1. The
    following clocks decrement by 2.
  - At timeout OUT goes low and the count reloads. The first clock after the
    reload decrements by 3, the following clocks by 2.
  - OUT is high for (N+1)/2 and low for (N−1)/2 clocks.
  - In Fig. 7, n=5: 5 4 2, then 5 2.
- **GATE**: the same as mode 2. Low disables counting and sets OUT high at
  once; a rising edge reloads and initiates (Fig. 6).
- **Rewrite**: not stated for mode 3 beyond "similar to MODE 2". By analogy
  the new value takes effect at the next reload **[derived]**.
- **N = 1, 2, 3**: not given.

### Mode 4 - software-triggered strobe

- **After the control word**: OUT is high (DS p.3-55; CM).
- **Count loaded**: counting begins. At terminal count OUT goes low for one
  CLK period, then high again. In Fig. 7: WR n=4, then 4 3 2 1 0 with OUT
  low during 0.
- **GATE (level)**: low inhibits counting and high enables it (p.3-55,
  Fig. 6). GATE does not affect OUT. In Fig. 7 the count holds at 4 while
  GATE is low.
- **Rewrite**: during counting, the new count is loaded on the next CLK
  pulse (p.3-55). The mode does not reload by itself.
- **One byte of an RL=11 pair**: what happens when only the first byte is
  rewritten is not given in DS. MP says it has no effect **[secondary]**.

### Mode 5 - hardware-triggered strobe

- **After the control word**: OUT is high in Fig. 7. Not given in text.
- **Trigger**: counting starts after the rising edge of GATE. At terminal
  count OUT goes low for one clock period (p.3-55).
- **Retriggerable**: OUT does not go low until a full count after the latest
  rising edge. In Fig. 7: 4 3, then 4 3 2 1 0. Gate levels have no effect
  (Fig. 6: rising edge initiates counting).
- **Rewrite during counting**: not given. CM says only that a new rising
  edge restarts the count.

### Summary (DS Fig. 6, p.3-55, plus the text)

| Mode | OUT after control word | GATE low / going low | GATE rising | GATE high | Reload |
|---|---|---|---|---|---|
| 0 | low | disables counting | - | enables | no |
| 1 | high [diagram] | - | initiates counting; OUT low after the next clock | - | on trigger |
| 2 | high | disables counting; OUT high at once | reloads, initiates | enables | auto at TC |
| 3 | high | disables counting; OUT high at once | reloads, initiates | enables | auto at TC |
| 4 | high | disables counting | - | enables | no |
| 5 | high [diagram] | - | initiates counting | - | on trigger |

  - CIN ≤ 10 pF, CI/O ≤ 20 pF.

## 8. Power-on

- Before initialisation, the **mode, the count and the output of every
  counter are undefined** (DS p.3-54). The chip has no reset pin (DS Fig. 2).
- KS and CM say nothing about the power-on state.
- Which defined state the model should power up in is a project choice.

## 9. 8253 vs 8254 and the Soviet part

**The ВИ53 is the 8253** (WP; CM; KS p.1 pinout and timing equal DS). It
therefore lacks the following 8254 features:

- No read-back command: SC=11 is illegal (DS p.3-54).
- No status byte.
- No defined behaviour for interleaved reads and writes. DS only forbids
  them (p.3-58). The 8254 tolerates them (MP [secondary]).

The 8254's mode 3 odd-count algorithm differs. DS: −1 first, then −2; after
the reload −3 first. The 8254 instead loads N−1 and counts by 2, with the
same waveform (MP [secondary]). A model of the 8253 must use the DS
algorithm, because reads in mode 3 return different intermediate values
**[derived]**.

The 8254 datasheet's detailed per-mode CLK-pulse tables are **not** in DS.
Using them for the ВИ53 is an assumption.

Differences found between the Soviet sources and DS:

| Item | DS (8253) | Soviet source |
|---|---|---|
| VCC tolerance | ±10 % | ±5 % (KS p.1) |
| Max clock | 2.6 MHz (tCLK 380 ns) | 2 MHz for ВИ53, 2.5 MHz for ВИ53Д (CM, WP); KS still gives 380 ns |
| Ambient | 0..70 °C | −10..+70 °C (KS p.3) |
| Speed grades | 8253 and 8253-5 | KS gives one set, equal to the 8253 column |
| OUT pins | outputs | KS p.1 calls them "входы" (KS error) |

No functional (logic) difference between the ВИ53 and the 8253 is
documented in any source found.

## 10. Open questions

1. **-CS/-RD/-WR sampling.** Is a write latched at -WR↑ only, or does the
   register follow the bus while -WR is low? Is the count byte for a read
   sampled at -RD↓? DS only implies the -WR↑ capture (§2.2).
2. **Byte flip-flop.** Do reads and writes share one LSB/MSB flip-flop, and
   what does a broken sequence do? Does a mode word reset the flip-flop?
   (§4.2)
3. **RL=01/10.** What happens to the byte that is not written (zero or
   kept)? (§3)
4. **Second latch.** Is a second latch command before the read ignored?
   What does a write to a latched counter do? (§4.3)
5. **SC=11 and -RD/-WR together**: behaviour not given.
6. **Modes 1 and 5.** OUT and count from the control word to the first
   trigger. How is the GATE edge captured (latched asynchronously, or
   sampled at CLK↑)? The tGS/tGH figures suggest sampling at CLK↑.
7. **Mode 2 with N=1, and mode 3 with N=1..3**: not given.
8. **Mode 3 and mode 5 rewrites mid-count**: not stated.
9. **BCD with a non-BCD value**: not given.
10. **Exact OUT edge.** Does OUT change at the CLK↓ that reaches the count
    (1 in mode 2, 0 in the others), as Fig. 7 draws it? Confirm against the
    real chip or a die-level source.
11. **Power-on state**: undefined in DS. A model choice is needed.
12. **Soviet max clock.** The 2 MHz (CM, WP) and 380 ns (KS) figures
    conflict. The board's 2 MHz is within both, so this does not affect the
    model.

## 11. The model's choices (`rtl/chips/kr580vi53*.sv`)

Where the sources leave it open, the model takes:

| Place | Chosen |
|---|---|
| Write | taken as -WR rises, the bus as it stood a master tick before |
| Read | the count byte driven while -CS and -RD are low; the pointer moves as -RD rises |
| Byte pointers | one for reads, one for writes, both reset by a control word |
| RL = 01 / 10 | the byte not written is 0 |
| SC = 11 | ignored |
| A second latch command | ignored until the latched value has been read |
| GATE | sampled as CLK rises; a rise between two samples is a trigger; modes 2 and 3 force OUT high while GATE is low, at once |
| Modes 1, 4, 5 after terminal count | the counter stops (not given) |
| Mode 2, N = 1 | OUT stays low (not given) |
| BCD with a non-BCD count | a decade at 0 borrows and becomes 9 (not given) |
| Power-on | registers zero, no count loaded, OUT low until a control word |
